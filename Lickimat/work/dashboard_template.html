Profit lost to stockouts each week

Out-of-stock SKUs only: weekly demand × profit per unit. Weekly demand uses the 90-day rate when that is higher, so an empty shelf does not hide demand. Loss-making SKUs count as 0. Uses sales and the economics file only, none of the assumed settings. Follows the Market filter only.

Replenishment list

Sorted by priority. Click a column header to sort.
SKU: the bold part is the base code (the LickiMat product code); the rest is the label or marketplace suffix. "unmapped" = no LM product code (bundles, test listings).
Order: by status number (1 · Out of stock first); within a status, the highest profit at stake per week first. Click any column header to sort differently; Reset returns to this order. Loss-making SKUs are restocked like any other (brand presence) and keep the Losing money flag. Profit /unit = net proceeds ÷ units sold over the economics window ("est." = the market's median, no match). Profit at stake /wk = demand per week × profit per unit. Demand, cover and profit are rounded for reading; the CSV keeps exact values, in the market's currency (converted to GBP at fixed rates only to order mixed markets).
Cover = (available + inbound) ÷ weekly demand; "no sales" = no demand to divide by, so cover is not counted as 0. Restock recommendation = our rule-based quantity (see Rules & assumptions). Amazon recommendation = "Recommended ship-in quantity" (UK, US) or "recommended-order-quantity" (AU) from Amazon's own restock report. Mich = Mich's reco sheet for the same date (blank if Mich did not review the SKU). New inbound = rise in inbound units since the previous snapshot.
